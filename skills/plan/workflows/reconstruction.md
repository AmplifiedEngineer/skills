# Architecture Reconstruction

## Purpose
Reconstruct the actual architecture of an existing system.

## Required references
- `../references/repository-investigation.md`
- `../references/evidence.md`
- `../references/knowledge-model.md`

## Procedure
1. Establish repository boundaries and workspace structure.
2. Identify languages, frameworks and runtime environments.
3. Inspect entry points and execution flows.
4. Identify modules, components and architectural boundaries.
5. Trace dependencies and integrations.
6. Investigate persistence and data flows.
7. Inspect authentication and security boundaries.
8. Examine deployment and infrastructure configuration.
9. Inspect testing, CI/CD and observability.
10. Identify architectural patterns and inconsistencies.

## Rules
- Inspect actual implementation, not just documentation.
- Do not infer runtime behaviour solely from filenames.
- Trace important dependencies to their implementations.
- Mark incomplete investigations explicitly.
- Avoid exhaustive inspection when the task has a narrower scope.

## Output
- System context
- Component inventory
- Dependency overview
- Data and integration flows
- Technology inventory
- Architectural patterns
- Findings and confidence levels
- Unknowns and investigation gaps
