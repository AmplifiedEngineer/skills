# Documentation Update

1. Identify documents linked to changed components or contracts.
2. Determine whether the change affects user guidance, APIs, operations, architecture or decisions.
3. Update the existing authoritative document where practical.
4. Avoid duplicate or speculative documents.
5. Preserve traceability to requirements and decisions.
6. Review documentation against the final implementation.
7. Include documentation changes in the implementation report.

If no documentation change is warranted, state that briefly when relevant.
