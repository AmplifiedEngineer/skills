# Evidence and Source Authority

Approved requirements establish expected outcomes. Accepted architecture decisions establish intended design. Repository implementation evidences current implementation. Tests and operational records evidence observed behaviour. Tickets and discussions may contain proposals or historical context. Documentation may be stale.

When sources conflict:
1. Identify the exact conflict and affected claim.
2. Compare source role, status, owner and freshness.
3. Do not silently choose a source when authority is unclear.
4. Report the discrepancy and its effect.
5. Request a decision only when it changes the recommended action.

Attach direct links or repository paths to material claims. Label observations, inferences, assumptions and unknowns.
