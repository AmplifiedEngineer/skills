# Architecture Drift Analysis

## Purpose
Compare documented and intended architecture against actual implementation.

## Required references
- `../references/evidence.md`
- `../references/knowledge-model.md`
- `../references/document-lifecycle.md`

## Procedure
1. Identify authoritative architecture documents and decisions.
2. Identify relevant implementation evidence.
3. Compare components, boundaries and responsibilities.
4. Compare dependency direction and integration contracts.
5. Compare data ownership and flows.
6. Compare security and operational assumptions.
7. Identify undocumented implementation changes.
8. Identify obsolete or inaccurate documentation.
9. Classify discrepancies and their consequences.
10. Recommend reconciliation actions.

## Output
- Scope and sources
- Confirmed alignment
- Architectural deviations
- Documentation discrepancies
- Risk assessment
- Recommended actions

Do not assume documentation is correct merely because it is authoritative.
Do not assume implementation is correct merely because it is current.
