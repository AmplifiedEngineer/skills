# PR body template

Fill this in order. Drop every optional part that has nothing to say. Aim for about 500 characters and stay under 1200.

```markdown
PROJ-123

## Summary

<What changed and why, in at most 3 short sentences. No file list, no restating the title.>

## Notes for reviewers

- <Optional. A risk, a decision, or a manual check CI cannot do. Drop the section when empty.>

## Related work

- <Optional. Links to the other PRs of a stack. Drop the section when empty.>
```

## Rules

1. First line: the ticket key (`[A-Z][A-Z0-9]+-[0-9]+`) when one is known, as a link when you know the tracker URL. No key means no line, and the body starts at `## Summary`. Never invent a key.
2. When the PR handles a GitHub issue, end the Summary with `Closes #N` if it fully resolves it, or `Refs #N` if it only advances it.
3. Summary is the only required section.
4. Leave out: a "What changed" or "Test plan" section, checklists of obvious steps, file lists, emoji headers, hedging, an "N/A" section, and any "generated by" footer. A Test plan is allowed only for manual steps a reviewer cannot get from CI.
5. No AI attribution, and no em or en dashes outside code.

## A correct body

```markdown
PROJ-123

## Summary

The sync job now retries up to three times when the queue is busy. Before, one busy reply dropped the whole run. Closes #41
```
